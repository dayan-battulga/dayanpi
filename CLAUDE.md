# dayanpi: notes for Claude Code

## What this repo is
A FastAPI dashboard for my Raspberry Pi 5 (focus tracker, stats, camera). Right now I'm building a focus tracker: the webcam sits at my desk and the site shows whether I'm working, on my phone, or away. docs/MANUAL.md explains how the app runs, and docs/ has a guide per add-on. If anything in this file disagrees with the code or the docs, trust those and tell me.

## Where things are
- All the Python lives in one package, dayanpi/, split by what it talks to: app.py (FastAPI), paths.py (STATIC_DIR, MODELS_DIR, DEFAULT_DATA_DIR, FOCUS_CHECK_DIR), hardware/ (camera, collector, voice, llm), vision/ (detector, hands, gestures), focus/ (tracker, worker, stats, check, todos, days, coach), auth/ (accounts.py: the SQLite store for users, sessions, invites and Mac tokens, password hashing and the lockout; no FastAPI in it. routes.py: the APIRouter app.py includes, with every account route (login, logout, join, me, password, tokens, invites, accounts), SESSION_COOKIE, Viewer, find_viewer/read_viewer/read_bearer, the cookie helpers, TAILSCALE_LOGIN and is_from_my_devices (the one Tailscale-User-Login check, for the camera lock and the sign-in), and the `accounts` and `lockout` globals the middleware uses and tests monkeypatch), utils/ (threads, files), static/ (the dashboard's build output from web/: never edit it by hand). Import with the full path (`from dayanpi.focus.tracker import FocusTracker`), never a bare module name.
- Outside the package: web/ (the dashboard's source, see Dashboard below), design/ (the approved design: SPEC.md, mockups/, fixtures/; see Design below), models/ (ONNX files), tests/, mac_helper/, deploy/ (dayanpi.service, dayanpi.env.example), docs/ (MANUAL.md for setup and running, plus one guide per add-on: focus-tracker.md, pi-camera.md, voice.md), and the gitignored data/ and focus_check/ written on the Pi. pyproject.toml sets pytest's testpaths and pythonpath, so plain `pytest` from the repo root works.
- A new module goes in the package folder that matches what it talks to; a new thing you run by hand gets a main() and runs with `.venv/bin/python -m dayanpi.<module>` from the repo root, like dayanpi.focus.check and dayanpi.focus.stats. Nothing that imports the package goes at the repo root.

## How it runs
- Code gets pushed to main, either by you from a cloud session or by me from my Mac. I pull on the Pi at ~/Desktop/site-page/dayanpi and run `sudo systemctl restart dayanpi`.
- uvicorn serves `dayanpi.app:app` on 127.0.0.1:8000 under systemd (deploy/dayanpi.service, runs as user dayoon; a change to that file needs `sudo cp deploy/dayanpi.service /etc/systemd/system/` and `sudo systemctl daemon-reload` on the Pi). Tailscale Serve/Funnel exposes it at https://dayoon.tail279594.ts.net.
- Accounts: dayanpi/auth/ keeps users, sessions, invites and Mac tokens in SQLite at data/accounts.db (find_data_dir(), so DAYANPI_DATA_DIR moves it; stdlib sqlite3, one connection, one threading.Lock around every use, PRAGMA foreign_keys=ON so removing a user cascades to its sessions and tokens; ids are AUTOINCREMENT, so a removed account's, token's or invite's id never comes back for the next one). At most 4 accounts: the owner (me) and members. Passwords are hashlib.scrypt (n=2**14, r=8, p=1, 16-byte salt per user) stored as "scrypt$16384$8$1$salt$hash" and compared with hmac.compare_digest; sessions, invite codes and tokens are random and stored only as sha256 hex. Never log a password, session, invite code or token: invite codes only ever sit in the /join/<code> page path, and app.py's filter on the uvicorn.access logger rewrites that to /join/….
- Every HTTP route sits behind the session middleware in dayanpi/app.py (Basic Auth is gone). The cookie is __Host-dayanpi_session (HttpOnly, Secure, SameSite=Lax, Path=/, no Domain, 30 days; refreshed on use once it was last extended over an hour ago, so the DB isn't written every request). No session: /api/* and /video* get 401 {"detail": "sign in first"}, other GETs a 303 to /login?next=<path>, anything else 401. Public without a session: GET /login, /join/<code>, /api/health and /assets/* (no ".." or backslashes), and POST /api/login, /api/join, /api/logout, matched exactly. /login, /join/<code>, /settings, /me and /pi serve static/index.html (app.page, a new client route needs its line there and a row in tests/test_app.py's ACCESS); / still comes from the StaticFiles mount, and the page sends it on to /me. The middleware does not run for WebSocket connections, so app.WebSocketGate (outermost) closes every handshake with 1008 before the routes; don't add WebSocket routes.
- Writes must be JSON: before auth, any POST/PUT/PATCH/DELETE whose Content-Type isn't exactly application/json gets 415 {"detail": "send JSON"}, so a plain form on another site can't post (that's the CSRF guard, and it covers login, join and logout too). Right after that, a write with Transfer-Encoding, no numeric Content-Length, or one over app.MAX_BODY_BYTES (64 KB) gets 413 {"detail": "too big"} (is_body_small), so a bigger write or an upload route needs that cap raised. The page sends a JSON body on every write, "{}" when there's nothing. app.refuse_invalid_request replaces FastAPI's 422 with where and what was wrong, never the value sent: the default echoes a password back, and a lone surrogate or NaN turns it into a 500 whose traceback logs the body. Keep it for every new model.
- Members are read-only on my data until they get their own desk. Default deny: a member's POST/PUT/PATCH/DELETE (session or token) is a 403 unless "METHOD /path" fullmatches app.MEMBER_WRITES, a regex of their own account things (PATCH /api/me, POST /api/me/password, POST /api/tokens, DELETE /api/tokens/<id>; /api/logout is in PUBLIC_WRITES, so it never gets that far), and owner-only reads are a second short list (OWNER_READS: /api/stats, /api/invites, /api/accounts). So a new write route is owner-only unless someone adds a "METHOD /path" alternative to MEMBER_WRITES; a bare path never matches. Handlers still check "own" (someone else's token is a 404). /api/stream works for members but each event carries only "focus", no Pi stats, and every stream re-checks its session each tick and ends when it's gone (signed out, account removed).
- Invites: the owner makes them in Settings; one-time, 7 days, and none work once there are 4 accounts. The join API takes the code in its JSON body; using the invite, the 4-account check and making the user happen in one transaction under the store's lock.
- Wrong passwords: auth.accounts.LoginLockout counts misses per lowercased username, unknown ones too; misses 1-4 are free, the 5th starts a 30 s wait that doubles after each later miss up to 15 min, tries during a wait are refused without checking. Every failure is the same 401 "wrong username or password", and unknown names still run scrypt on a dummy hash. It's in memory, so a restart clears it, and it isn't really per name: each name lands in one of 65536 buckets (LOCKOUT_BUCKET_BYTES = 2) by a blake2b hash keyed with a random key made at startup, so it can't grow and nobody can pick a name that collides with yours. Two names in one bucket share one wait, and a sign-in on either clears both; that's on purpose, so don't "fix" it into a per-name map or test for per-name counts. A sign-in where routes.is_from_my_devices() is true skips it entirely (check_sign_in(from_my_devices=True)): no wait, no miss counted, and a success doesn't clear what strangers ran up; with DAYANPI_TAILSCALE_LOGIN unset nothing skips. Every scrypt (hash or check) goes through routes.run_scrypt_work, two at a time on its own scrypt_pool (16 MB each), never on the event loop or the shared thread pool. The password change has its own wait, routes.password_lockout (429 "too many tries, wait a bit"), so strangers missing at /api/login can't block it; each wrong current password also counts toward the sign-in's.
- Mac tokens (dpi_..., made in Settings, shown once, revocable) go in Authorization: Bearer and only count on paths under /api/mac/, where the cookie is ignored; a Bearer header anywhere else is a 401. A token acts as its user (a member's token still gets 403 on POST /api/mac/app) and never opens /video. The helper keeps it in the same Keychain item the password used to be in (service dayanpi, account DAYANPI_USER) and sends it with add_unredirected_header, so urllib never forwards it on a redirect.
- No per-minute rate limits (slowapi is gone: it sat behind the auth middleware, so it only ever throttled me, and behind Tailscale every request shares 127.0.0.1). The expensive streams have connection caps instead: /video and /video/side allow 2 at once each and /api/stream 5 per account (threading.BoundedSemaphore in app.py, one per user id for the stream); past that they return 503. SlotResponse gives a slot back as soon as its stream ends, because a finally in the generator would wait for the garbage collector.
- Startup fails if DAYANPI_USER or DAYANPI_PASSWORD is missing (they only make the owner when accounts.db has no users; after that they're ignored unless accounts.db is gone), or if /sys/class/net/wlan0 doesn't exist (sampler.sample() runs at startup). A missing camera doesn't stop startup: stream.start() logs a warning and the capture loop keeps retrying.
- You run in a cloud session or on my Mac, never on the Pi. You can't reach the Pi, its GPIO, or its camera. When something needs the Pi, give me the exact commands and I'll run them.

## Focus tracker
- The webcam is at my desk now, pointed at my face, hands and desk. Plan, one step at a time: (1) detector check, (2) turn detections into steady states (working / phone / away), (3) run it inside the app and log state changes on the Pi, (4) dashboard card with the current state, today's totals and a timeline, (5) extras. Steps 1-4 are done.
- The pieces: vision/detector.py (models), focus/tracker.py (FocusTracker state machine, DayTotals, Callouts, FocusLog, replay_day/total_day), focus/worker.py (the thread that scans a frame from each camera about once a second and feeds the tracker; it reads with frame_after() and a last frame id per camera, so a frozen camera means "no frame", never a re-scan of a stale picture, and it waits up to 60 s for systemd-timesyncd's sync file before the first check because the Pi's clock can be hours off at boot), utils/threads.py (LoopThread: the shared start/tick/stop base for the worker and the coach; a tick that raises is logged, rate-limited, and never kills the thread), focus/stats.py (CLI over the log, run with python -m dayanpi.focus.stats), focus/merge.py (merge_readings: people and phones from both cameras, faces and hands from the front only, elapsed_ms is the sum; the merged boxes mix two cameras' coordinates, so only their confidences mean anything), focus/overlay.py (the latest check as boxes in 0-1 fractions of the frame, same cutoffs as the rules, built from each camera's own reading; the worker keeps them as last_overlay and last_side_overlay, build_focus_status sends them as "overlay" and "side_overlay" with age_s, the page draws each one over its own feed and drops it after 3 s (web/src/hooks/useOverlayBoxes.ts); never logged). app.py starts the worker in lifespan, restores today from the log first, puts build_focus_status() into every SSE snapshot as "focus", and serves /api/focus (status plus segments), /api/todos (GET, POST) and /api/todos/{item_id} (PATCH, DELETE), /api/days?month=YYYY-MM and /api/days/{day}, and /api/mac/app.
- The rules live as constants at the top of focus/tracker.py: person >= 0.5 for 2 checks = present; phone >= 0.5 in 3 of the last 5 checks = on phone, out after 5 misses; 10 s without a person = away; 30 s without frames = unknown. The detector only keeps person and phone (each box counts only for its best class out of all 80, which keeps a mouse or TV remote from counting as a phone). Every time-based rule takes `now` from the caller; tests drive it with fake clocks.
- The log is data/focus_log/YYYY-MM-DD.jsonl (DAYANPI_DATA_DIR overrides data/). Lines: state, pickup, callout, mac_app (app, and site: a browser tab's host name or null), sample (every 30 s, with app and site; side_person and side_phone only when the side camera gave a frame), day_summary, day_start, restart. Never frames. Logs from before snacks and work blocks were removed still have snack and block lines and food/drink/side_food/block fields; replay_day, total_day, focus.stats and the day pages ignore them (tests/test_focus.py has an old log). FocusTracker.restore() rebuilds today from it after a restart (loses at most 30 s): replay_day() treats day_start like a state line and a restart line as a boundary (the open segment closes at the line before it), so a dead Pi never counts as focus time. A torn line is skipped, not fatal. _accumulate caps one update at MAX_STEP_S so an NTP clock jump adds seconds, not hours.
- focus/todos.py: TodoList, the running to-do list in data/todos.json (find_data_dir() / todos.json; saved whole to a .tmp and os.replace'd; an unreadable file is moved to todos.json.broken, never saved over). One current item collects seconds via track(), which app.handle_focus_update calls after every check with state == "working" (same MAX_STEP_S cap as the tracker; time saves every 30 s, edits right away). Done items leave at local midnight. Logs "todo" lines (action added/done/undone/current, id, text, seconds); replay_day ignores them. build_focus_status sends snapshot() as "todos".
- Sites: mac_helper/dayanpi_mac_helper.py reads the active tab's URL through osascript only for Google Chrome, Brave Browser, Microsoft Edge (Chromium's window "mode" must be "normal") and Arc (window "incognito" must be false); every script checks "is running" first and fails closed, so a window it can't confirm as normal sends no site. Safari has no private-window property in its scripting dictionary and Firefox has no tabs, so both send no site (logged once). find_site keeps only the host name (lowercase, no www., punycode, no port or login) and SITE_PATTERN matches app.SITE_PATTERN, so the Pi never 422s a site the helper sends. The helper posts {"app", "site"} when either changes (same heartbeat and backoff); /api/mac/app takes site as optional (max 253, plain host name pattern). tracker.record_app(app, now, site) logs a mac_app line when either changes and puts site on samples and the status; days.count_mac_seconds counts SAMPLE_LOG_INTERVAL_S per sample toward its app while working or phone, the app isn't Locked and tracking isn't paused (top 10, the page's Apps section), and toward YouTube when the site is youtube.com or a subdomain (Totals and youtube_minutes); no other site is counted. tracker.MAC_STALE_S (150 s, the helper heartbeats every 60 s) clears the current app and site when the helper goes quiet, so a sleeping Mac neither shows nor counts. Never full URLs, paths, queries or titles.
- Mac tracking switch: focus/mac_tracking.py (MacTrackingSetting, data/mac_tracking.json {"enabled"}, on by default, write_atomically) is the saved pick; tracker.set_mac_tracking(enabled, now) holds the live flag under the tracker lock (record_app drops reports while off, so no race with a flip), clears app/site when off, and logs a mac_tracking line. app calls it on each change through POST /api/mac/tracking (StrictBool), at startup when the saved pick is off, and the tracker itself writes one after day_start while off. /api/mac/app replies with "enabled"; build_focus_status sends "mac_tracking". days.count_paused_seconds sums mac_tracking false..true (an open pause runs to the day's last line) and count_mac_seconds skips samples while paused; no lines = on. The helper's TrackingSwitch GETs /api/mac/tracking every TRACKING_CHECK_S (10 s), also hears "enabled" off each report reply, skips all detection while off, and calls AppReporter.resend() on resume; send_request returns Reply(status, body). The dashboard's web/src/components/mac/MacLine.tsx (the Desk's Mac line, at the right of the stats row) says "On the Mac · <app>", "On the Mac · <site> in <app>", "Mac tracking paused" or "The Mac isn't reporting" (Desk's mac option); its Pause/Resume text button (owner only, none while not reporting) and ⌘K's command both go through the frame's hooks/useMacTracking, which flips optimistically, holds the pick SWITCH_HOLD_S against a late snapshot, drops the hold on a failed POST and says so in a toast.
- focus/days.py: one markdown page per finished day, data/days/YYYY-MM-DD.md (find_days_dir()), built by build_day_page() from that day's log lines: totals via replay_day/total_day, and to-dos whose last done/undone line that day is done. The numbers are also frontmatter, which read_page_totals() reads back for the month route. app.day_page_writer (an asyncio task in lifespan) waits for the clock sync, then write_missing_pages() writes every past day with a log and no page, and again AFTER_MIDNIGHT_S after each local midnight; pages are never written over (write_atomically from utils/files.py, shared with todos). Today never gets a file: the routes build it live. The routes take the day/month through FastAPI patterns (DAY_PATTERN, MONTH_PATTERN), so a name can only be a file in data/days. The page side is web/src/components/calendar/ (a hand-built month grid, Sunday first, no react-day-picker; today's minutes from the stream; a day's page opens in a dialog) with lib/calendar.ts (month math) and lib/markdown.ts (reads only the subset the pages use, into React text, never HTML).
- Callouts (tracker.Callout; speak=False means log only, which nothing uses since break_over went): instant_pickup, late_night_phone, long_break (back after LONG_BREAK_S, 15 min), day_done. app.handle_focus_update fans them out: speak=True goes to voice.say().
- focus/coach.py: what the peace sign says. collect_facts() (spoken clock, minutes to DAYANPI_BEDTIME (HH:MM, default 00:00; the small hours before 5 a.m. count as the evening before, so past bedtime = bedtime..05:00), the first SPOKEN_MAX open and done to-dos plus counts) feeds describe_todos() (the template, always there) and build_prompt(). With DAYANPI_LLM_MODEL set, TodoCoach (a LoopThread, every 2 s) keeps a Draft written by hardware/llm.py: rewritten when TodoFacts.key changes (the lists, the counts, past-bedtime) or every REWRITE_S (240 s); pick() speaks it only if its key matches and it's under MAX_AGE_S (300 s) old and clean_message() passed it (no list lines, markup, emojis, over 4 sentences or 400 chars, or numbers missing from the facts); otherwise the template. hardware/llm.py (OllamaClient) is the only thing that talks to Ollama: http.client to the fixed 127.0.0.1:11434 (no proxies, no redirects, no setting to change the host), /api/generate, stream false, num_thread 2, keep_alive 15m, 60 s timeout; it returns None and sets .problem on any failure. Tests use a fake Ollama HTTP server on 127.0.0.1:0, never the network.
- hardware/voice.py: VoiceAnnouncer speaks through ALSA aplay (a systemd system service can't reach the desktop's PipeWire). DAYANPI_VOICE = off (default, logs "would say") | piper; DAYANPI_PIPER_MODEL, DAYANPI_AUDIO_DEVICE. A voice that can't run logs one error and stays off.
- Phones only count in or near a hand: worker.check_hands runs the hand models on every camera's frame and keeps only phones whose box touches a hand box grown by NEAR_HAND_MARGIN (0.25 of the hand's longer side, hands.find_phones_in_hand), per camera before merging, since merged boxes mix coordinates. No hand models, or a hand model that throws, means phones count anywhere, as before. The overlay is built after that, so the peek only boxes phones that count.
- Hand signs: vision/hands.py (HandScanner: OpenCV Zoo's MediaPipe palm detector, 192x192 NHWC, then the hand pose model on a 224x224 crop turned fingers-up by one warpAffine; 21 joints in frame pixels, MediaPipe numbering) runs on every camera's frame in worker.check_hands, into FrameReading.hands; signs only use the front's (merge_readings keeps those), and a hand model that throws costs only the signs, never the focus check. worker.build_hand_scanner() returns None with one log line when a file is missing. gestures.read_sign: a finger is open when its tip is farther from the wrist than its middle joint, and "v" means the index and middle tips are V_SPREAD (1.8) times as far apart as their knuckles (x and y only), so two fingers side by side on a mouse aren't peace; HAND_SIGNS is one rule per sign over those keys (thumb not read), held through worker.signs, a GestureTracker, via hold() ("hands down" = no sign). Fired signs go through the worker's on_gesture hook: app.handle_gesture logs a gesture line, then app.SIGN_ACTIONS maps the sign to what it does and returns extra fields for the gesture line (peace -> say_todos -> coach.pick, logged as spoken=llm|template). worker.last_gesture ({name, at}) goes out as status "gesture" with age_s, and web/src/hooks/useGestureToast.ts puts each new one in a 4 s toast (a new one = the age went down, since every snapshot repeats the last sign), except peace: say_todos keeps app.last_spoken ({text, at}, never logged) and build_focus_status sends it as "spoken" with age_s and speaking (VoiceAnnouncer.is_saying: from say() until aplay has played it or it failed, counted per phrase), and web/src/components/frame/PeacePill.tsx shows it under the top bar while speaking or for at least SHOW_S (6 s), keyed on its at. The front overlay boxes a hand (kind "hand") only while it makes a sign, labeled with the sign; plain hands get no box, and the side overlay gets no hands at all (worker passes it hands=[]). A new sign = a HAND_SIGNS line + a HOLD_SECONDS entry + a SIGN_ACTIONS line.
- app.py calls logging.basicConfig(INFO) at import, because uvicorn only configures its own loggers and the app's INFO lines would otherwise never reach journalctl.
- vision/detector.py runs two ONNX models through plain OpenCV (cv2.dnn and cv2.FaceDetectorYN), so the Pi needs no new pip packages. The models live in models/ (the hand models are separate, see Hand signs): YOLO26 nano (COCO, exported at 640x480, the default export with output (1, 84, 6300), not the NMS-free (1, 300, 6) one; class 0 = person, 67 = cell phone) and YuNet for faces.
- Phones come from a second YOLO pass on a crop around the main person (person >= 0.5, box plus margin); full-frame phone hits are ignored. On my real desk frames (measured with YOLO11n; YOLO26n hasn't been measured yet) that took a phone in hand from 10% to 80% of checks at >= 0.3, with no hits while working. It roughly doubles the time per check.
- hardware/camera.py is the only thing that may open the camera. Inside the app, read frames from app.stream (camera.create_stream() picks the backend: DAYANPI_CAMERA = auto (default) | usb | picamera | both; PiCameraStream wraps picamera2 behind the same latest_frame/frame_after interface and skips USB webcams that libcamera also lists). Frame sizes differ by camera: the webcam is 640x480 (FRAME_WIDTH/HEIGHT), the Pi camera 768x432 (PICAMERA_WIDTH/HEIGHT, 16:9 like the sensor; a 4:3 size makes the ISP crop the Wide lens's sides). Nothing downstream may assume 640x480: the detector letterboxes any size into the model input, the zoom crop and YuNet use the frame's own size, overlays carry frame_width/frame_height, and the dashboard fits each whole picture inside its fixed tile in that shape (camera/Feed.tsx's --ratio, from the overlay or the picture itself; .cam-picture sizes itself with container query units), so the boxes stay on it. With both, app.stream is the front camera and app.side_stream the other one (camera.create_side_stream(), None for every other setting), served at /video/side, a 404 when there's no side camera. DAYANPI_FRONT_CAMERA = usb (default) | picamera picks the front one; a bad value warns once and means usb, and it's never read without both. Everything downstream (faces and hand signs, the side_* sample fields, /video vs /video/side, the Front/Side captions) goes by front vs side, never by USB vs Pi camera. camera.find_usb_device() finds the webcam: DAYANPI_USB_DEVICE if set, else the first /dev/v4l/by-id/*-video-index0, else /dev/video0, since /dev/video0 can move once a CSI camera is plugged in. DAYANPI_PICAMERA_ROTATION = 0 (default) | 180 flips every Pi camera stream (picamera, auto, front or side with both) through libcamera's Transform(hflip=1, vflip=1) in the camera's own ISP, read once per PiCameraStream; the webcam is never flipped. Both cameras go through the detector. /pi shows them as tiles side by side (Pi.dc.html; web/src/components/camera/CameraCard.tsx, a Side tile only when the status says side_camera), and the page only opens the feeds while peeking (Peek opens both, remembered in localStorage). Standalone tools like dayanpi.focus.check need `sudo systemctl stop dayanpi` first.
- Never save video or frames on the Pi, except the detector check's snapshots in focus_check/ (gitignored). Only state changes get logged.
- The site can be on Tailscale Funnel, but the full camera feeds only answer the owner on my own Tailscale devices. Serve adds a Tailscale-User-Login header for my tailnet devices and strips a client's copy; Funnel requests never have it. With DAYANPI_TAILSCALE_LOGIN set, /video and /video/side need the owner's session (not a token) AND that header exactly equal to it (no case folding, no strip); anything else is a 404, the same for members, a wrong login and no header. Unset, the camera works for the owner like before and startup logs one warning (camera not locked to Tailscale, don't turn on Funnel); set, one info line. The focus status (in /api/focus and every stream event, worked out per request, never cached in the shared snapshot) has "camera_access": open | tailscale_only | owner_only, and when it isn't open, "overlay" and "side_overlay" are null and /pi's tiles are locked, with no Peek and no img at all. Trap: a request straight to 127.0.0.1:8000 skips Serve, so it can carry any header it likes. That's only safe because uvicorn binds 127.0.0.1, so never bind it to 0.0.0.0.

## Dashboard (web/)
- web/ is the dashboard's source: React + TypeScript + Vite + Tailwind CSS v4 + shadcn/ui, Lucide icons, Geist from @fontsource-variable (the page loads nothing from the internet; tests/test_app.py checks every file it links is a local /assets/ file). `npm run build` type-checks and writes dayanpi/static/ (Vite outDir, emptied first). dayanpi/static/ is build output: never edit it by hand, and commit it with every web/ change so the Pi never needs Node. The lockfile is committed; use `npm ci`.
- `npm run dev` proxies /api and /video to the Pi at DAYANPI_URL from web/.env.local (gitignored; web/.env.example has it). That's the only setting it needs: you sign in on the dev page itself, in Chrome, which keeps the Pi's Secure session cookie on http://localhost (Safari drops it, so every request after the login is a 401). Only vite.config.ts reads it, never the page.
- Pages (React Router, src/App.tsx): /me (my desk: today's cards), /pi (owner only: Cameras and The Pi from Pi.dc.html, with the undervoltage warning; a member is sent to /me), /settings (name, password, sign out, Mac tokens; invites and accounts for the owner), and / (and anything unknown) goes to /me until the room exists. Those three sit inside components/frame/Frame.tsx, the layout route: the one stream (useSnapshot), useMe, the clock, the Mac tracking pick (hooks/useMacTracking: the optimistic hold, shared by the Mac card's switch and ⌘K, a toast on a failed POST), the top bar, the phone dock, ⌘K, the one Toaster, and React's <ViewTransition> keyed on the path (BrowserRouter already navigates inside startTransition); pages read all of it through useFrame() (outlet context), never their own useSnapshot/useMe. /login and /join/:code are outside it (no stream, no /api/me before you're signed in) with AuthFrame's slim bar. Settings, Pi, login and join are React.lazy, so /me doesn't download them. A 401 from any request sends you to /login and back to where you were afterwards.
- The frame (design/mockups Desk and RoomPhone): header/Header.tsx is the top bar (wordmark, the amber Reconnecting chip while the stream is down, the Desk/Pi tabs, ThemeToggle, AccountMenu as a round initial, ringed on /settings); PillLink's active link carries an m.span with layoutId that slides on SPRINGS.toggle. ## Ground rules
- You can commit and push to main. One commit per step, with a message that says what changed, and only after the tests for what changed pass. Finish with the list of changed files.
- One step at a time. Stop when a step is done and wait for me.
- No calls to outside services or endpoints unless I explicitly say so for that run.
- Code style for new code: noun-first class names, verb-first function names, one return per function, no tuple returns, repeated code goes in a utils module, descriptive names for returned values, comments only for real traps. The existing code (app.py, hardware/camera.py, hardware/collector.py) doesn't all follow these; don't refactor it to match unless I ask.
- Finish every step with the tests you ran (only the ones covering what changed) and their results, plus the exact commands for me to test it on the Pi.
- Write docs (like docs/MANUAL.md) in plain, casual language.
