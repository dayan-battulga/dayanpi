# dayanpi: notes for Claude Code

## What this repo is
A FastAPI dashboard for my Raspberry Pi 5 (focus tracker, stats, camera). Right now I'm building a focus tracker: the webcam sits at my desk and the site shows whether I'm working, on my phone, or away. docs/MANUAL.md explains how the app runs, and docs/ has a guide per add-on. If anything in this file disagrees with the code or the docs, trust those and tell me.

## Where things are
- All the Python lives in one package, dayanpi/, split by what it talks to: app.py (FastAPI), paths.py (STATIC_DIR, MODELS_DIR, DEFAULT_DATA_DIR, FOCUS_CHECK_DIR), hardware/ (camera, collector, voice, llm), vision/ (detector, pose, hands, gestures), focus/ (tracker, worker, stats, check, todos, days, coach), sign/ (renderer, glyphs, controller), utils/ (threads, files), static/ (the dashboard's build output from web/: never edit it by hand). Import with the full path (`from dayanpi.focus.tracker import FocusTracker`), never a bare module name.
- Outside the package: web/ (the dashboard's source, see Dashboard below), models/ (ONNX files), tests/, mac_helper/, deploy/ (dayanpi.service, dayanpi.env.example), docs/ (MANUAL.md for setup and running, plus one guide per add-on: focus-tracker.md, pi-camera.md, led-sign.md, voice.md), and the gitignored data/ and focus_check/ written on the Pi. pyproject.toml sets pytest's testpaths and pythonpath, so plain `pytest` from the repo root works.
- A new module goes in the package folder that matches what it talks to; a new thing you run by hand gets a main() and runs with `.venv/bin/python -m dayanpi.<module>` from the repo root, like dayanpi.focus.check and dayanpi.focus.stats. Nothing that imports the package goes at the repo root.

## How it runs
- Code gets pushed to main, either by you from a cloud session or by me from my Mac. I pull on the Pi at ~/Desktop/site-page/dayanpi and run `sudo systemctl restart dayanpi`.
- uvicorn serves `dayanpi.app:app` on 127.0.0.1:8000 under systemd (deploy/dayanpi.service, runs as user dayoon; a change to that file needs `sudo cp deploy/dayanpi.service /etc/systemd/system/` and `sudo systemctl daemon-reload` on the Pi). Tailscale Serve/Funnel exposes it at https://dayoon.tail279594.ts.net.
- Every HTTP route sits behind the Basic Auth middleware in dayanpi/app.py. That middleware does not run for WebSocket connections, so don't add WebSocket routes.
- No per-minute rate limits (slowapi is gone: it sat behind the auth middleware, so it only ever throttled me, and behind Tailscale every request shares 127.0.0.1). The expensive streams have connection caps instead: /video and /video/side allow 2 at once each and /api/stream 5 (threading.BoundedSemaphore in app.py); past that they return 503. SlotResponse gives a slot back as soon as its stream ends, because a finally in the generator would wait for the garbage collector.
- Startup fails if DAYANPI_USER or DAYANPI_PASSWORD is missing, or if /sys/class/net/wlan0 doesn't exist (sampler.sample() runs at startup). A missing camera doesn't stop startup: stream.start() logs a warning and the capture loop keeps retrying.
- You run in a cloud session or on my Mac, never on the Pi. You can't reach the Pi, its GPIO, or its camera. When something needs the Pi, give me the exact commands and I'll run them.

## Focus tracker
- The webcam is at my desk now, pointed at my face, hands and desk. Plan, one step at a time: (1) detector check, (2) turn detections into steady states (working / phone / away), (3) run it inside the app and log state changes on the Pi, (4) dashboard card with the current state, today's totals and a timeline, (5) extras. Steps 1-4 are done.
- The pieces: vision/detector.py (models), focus/tracker.py (FocusTracker state machine, DayTotals, Callouts, FocusLog, replay_day/total_day), focus/worker.py (the thread that scans a frame from each camera about once a second and feeds the tracker; it reads with frame_after() and a last frame id per camera, so a frozen camera means "no frame", never a re-scan of a stale picture, and it waits up to 60 s for systemd-timesyncd's sync file before the first check because the Pi's clock can be hours off at boot), utils/threads.py (LoopThread: the shared start/tick/stop base for the worker and the sign; a tick that raises is logged, rate-limited, and never kills the thread), focus/stats.py (CLI over the log, run with python -m dayanpi.focus.stats), focus/merge.py (merge_readings: people and phones from both cameras, faces and poses from the front only, elapsed_ms is the sum; the merged boxes mix two cameras' coordinates, so only their confidences mean anything), focus/overlay.py (the latest check as boxes in 0-1 fractions of the frame, same cutoffs as the rules, built from each camera's own reading; the worker keeps them as last_overlay and last_side_overlay, build_focus_status sends them as "overlay" and "side_overlay" with age_s, the page draws each one over its own feed and drops it after 3 s (web/src/hooks/useOverlayBoxes.ts); never logged). With the pose model, build_overlay(..., with_pose=True) adds "pose" to the front overlay only: the main person's 17 [x, y, confidence] in 0-1 fractions (None when no person >= PERSON_MIN); without it there's no "pose" key, which is how the page knows to hide Show pose (scanner.has_pose, True on PoseDeskScanner). The Camera card's Show pose toggle (localStorage) draws it as an SVG skeleton over the front feed with the frame's own viewBox (web/src/lib/pose.ts: LIMBS, buildSkeleton skips points under 0.5). app.py starts the worker in lifespan, restores today from the log first, puts build_focus_status() into every SSE snapshot as "focus", and serves /api/focus (status plus segments), /api/focus/block, /api/todos (GET, POST) and /api/todos/{item_id} (PATCH, DELETE), /api/sign/page (flip_page, same as the one-hand gestures; 503 when the sign is off), /api/days?month=YYYY-MM and /api/days/{day}, and /api/mac/app.
- The rules live as constants at the top of focus/tracker.py: person >= 0.5 for 2 checks = present; phone >= 0.5 in 3 of the last 5 checks = on phone, out after 5 misses; 10 s without a person = away; 30 s without frames = unknown. The detector only keeps person and phone (each box counts only for its best class out of all 80, which keeps a mouse or TV remote from counting as a phone). Every time-based rule takes `now` from the caller; tests drive it with fake clocks.
- The log is data/focus_log/YYYY-MM-DD.jsonl (DAYANPI_DATA_DIR overrides data/). Lines: state, pickup, callout, block, mac_app (app, and site: a browser tab's host name or null), sample (every 30 s, with app and site; side_person and side_phone only when the side camera gave a frame), day_summary, day_start, restart. Never frames. Logs from before snacks were removed still have snack lines and food/drink/side_food fields; replay_day, total_day and focus.stats ignore them (tests/test_focus.py has an old log). FocusTracker.restore() rebuilds today from it after a restart (loses at most 30 s): replay_day() treats day_start like a state line and a restart line as a boundary (the open segment closes at the line before it), so a dead Pi never counts as focus time. A torn line is skipped, not fatal. _accumulate caps one update at MAX_STEP_S so an NTP clock jump adds seconds, not hours.
- focus/todos.py: TodoList, the running to-do list in data/todos.json (find_data_dir() / todos.json; saved whole to a .tmp and os.replace'd; an unreadable file is moved to todos.json.broken, never saved over). One current item collects seconds via track(), which app.handle_focus_update calls after every check with "working and FocusUpdate.block_active" (same MAX_STEP_S cap as the tracker; time saves every 30 s, edits right away). Done items leave at local midnight. Logs "todo" lines (action added/done/undone/current, id, text, seconds); replay_day ignores them. build_focus_status sends snapshot() as "todos".
- Sites: mac_helper/dayanpi_mac_helper.py reads the active tab's URL through osascript only for Google Chrome, Brave Browser, Microsoft Edge (Chromium's window "mode" must be "normal") and Arc (window "incognito" must be false); every script checks "is running" first and fails closed, so a window it can't confirm as normal sends no site. Safari has no private-window property in its scripting dictionary and Firefox has no tabs, so both send no site (logged once). find_site keeps only the host name (lowercase, no www., punycode, no port or login) and SITE_PATTERN matches app.SITE_PATTERN, so the Pi never 422s a site the helper sends. The helper posts {"app", "site"} when either changes (same heartbeat and backoff); /api/mac/app takes site as optional (max 253, plain host name pattern). tracker.record_app(app, now, site) logs a mac_app line when either changes and puts site on samples and the status; days.count_site_seconds counts SAMPLE_LOG_INTERVAL_S per sample with a site while working or phone and the app isn't Locked (top 10, the page's Sites section). Never full URLs, paths, queries or titles.
- Mac tracking switch: focus/mac_tracking.py (MacTrackingSetting, data/mac_tracking.json {"enabled"}, on by default, write_atomically) is the saved pick; tracker.set_mac_tracking(enabled, now) holds the live flag under the tracker lock (record_app drops reports while off, so no race with a flip), clears app/site when off, and logs a mac_tracking line. app calls it on each change through POST /api/mac/tracking (StrictBool), at startup when the saved pick is off, and the tracker itself writes one after day_start while off. /api/mac/app replies with "enabled"; build_focus_status sends "mac_tracking". days.count_paused_seconds sums mac_tracking false..true (an open pause runs to the day's last line) and count_site_seconds skips samples while paused; no lines = on. The helper's TrackingSwitch GETs /api/mac/tracking every TRACKING_CHECK_S (10 s), also hears "enabled" off each report reply, skips all detection while off, and calls AppReporter.resend() on resume; send_request returns Reply(status, body). The dashboard's Switch (components/ui/switch.tsx, from the radix-ui package already installed) sits first in the Mac row, flips optimistically and drops its hold on a failed POST.
- focus/days.py: one markdown page per finished day, data/days/YYYY-MM-DD.md (find_days_dir()), built by build_day_page() from that day's log lines: totals via replay_day/total_day, blocks from block start/stop lines (carried over from the day before = starts at midnight; never stopped = ends at the last line, "still on"), and to-dos whose last done/undone line that day is done. The numbers are also frontmatter, which read_page_totals() reads back for the month route. app.day_page_writer (an asyncio task in lifespan) waits for the clock sync, then write_missing_pages() writes every past day with a log and no page, and again AFTER_MIDNIGHT_S after each local midnight; pages are never written over (write_atomically from utils/files.py, shared with todos). Today never gets a file: the routes build it live. The routes take the day/month through FastAPI patterns (DAY_PATTERN, MONTH_PATTERN), so a name can only be a file in data/days. The page side is web/src/components/calendar/ (a hand-built shadcn-style month grid, Sunday first, no react-day-picker; today's minutes from the stream) with lib/calendar.ts (month math) and lib/markdown.ts (reads only the subset the pages use, into React text, never HTML).
- Callouts (tracker.Callout, speak=False means sign/log only): instant_pickup, late_night_phone, long_break, break_over (during a block), day_done. app.handle_focus_update fans them out: speak=True goes to voice.say().
- focus/coach.py: what the peace sign says. collect_facts() (spoken clock, minutes to DAYANPI_BEDTIME (HH:MM, default 00:00; the small hours before 5 a.m. count as the evening before, so past bedtime = bedtime..05:00), the first SPOKEN_MAX open and done to-dos plus counts) feeds describe_todos() (the template, always there) and build_prompt(). With DAYANPI_LLM_MODEL set, TodoCoach (a LoopThread, every 2 s) keeps a Draft written by hardware/llm.py: rewritten when TodoFacts.key changes (the lists, the counts, past-bedtime) or every REWRITE_S (240 s); pick() speaks it only if its key matches and it's under MAX_AGE_S (300 s) old and clean_message() passed it (no list lines, markup, emojis, over 4 sentences or 400 chars, or numbers missing from the facts); otherwise the template. hardware/llm.py (OllamaClient) is the only thing that talks to Ollama: http.client to the fixed 127.0.0.1:11434 (no proxies, no redirects, no setting to change the host), /api/generate, stream false, num_thread 2, keep_alive 15m, 60 s timeout; it returns None and sets .problem on any failure. Tests use a fake Ollama HTTP server on 127.0.0.1:0, never the network.
- hardware/voice.py: VoiceAnnouncer speaks through ALSA aplay (a systemd system service can't reach the desktop's PipeWire). DAYANPI_VOICE = off (default, logs "would say") | piper; DAYANPI_PIPER_MODEL, DAYANPI_AUDIO_DEVICE. A voice that can't run logs one error and stays off.
- vision/pose.py + vision/gestures.py: with models/yolo26n-pose_480x640.onnx present (YOLO26 nano pose, in git, same (1, 56, 6300) output as YOLO11 nano pose), focus/worker.py uses PoseDeskScanner (pose model for the full-frame pass) and runs GestureTracker each check. Gestures: right hand up 1 s = next_page, left = previous_page, both 2 s = toggle_block. app.handle_gesture logs the gesture, toggles the block and speaks; page flips go to the sign controller.
- Phones only count in or near a hand: worker.check_hands runs the hand models on every camera's frame and keeps only phones whose box touches a hand box grown by NEAR_HAND_MARGIN (0.25 of the hand's longer side, hands.find_phones_in_hand), per camera before merging, since merged boxes mix coordinates. No hand models, or a hand model that throws, means phones count anywhere, as before. The overlay is built after that, so the peek only boxes phones that count.
- Hand signs: vision/hands.py (HandScanner: OpenCV Zoo's MediaPipe palm detector, 192x192 NHWC, then the hand pose model on a 224x224 crop turned fingers-up by one warpAffine; 21 joints in frame pixels, MediaPipe numbering) runs on every camera's frame in worker.check_hands, into FrameReading.hands; signs only use the front's (merge_readings keeps those), and a hand model that throws costs only the signs, never the focus check. worker.build_hand_scanner() returns None with one log line when a file is missing. gestures.read_sign: a finger is open when its tip is farther from the wrist than its middle joint; HAND_SIGNS is one finger rule per sign (thumb not read), held through a second GestureTracker via hold() (same hold rules as the arm gestures, "hands down" = no sign). Fired signs go through the same on_gesture hook: app.handle_gesture logs a gesture line, then app.SIGN_ACTIONS maps the sign to what it does and returns extra fields for the gesture line (peace -> say_todos -> coach.pick, logged as spoken=llm|template). worker.last_gesture ({name, at}) goes out as status "gesture" with age_s, and web/src/components/shared/GestureToast.tsx shows it for 4 s. The front overlay boxes a hand (kind "hand") only while it makes a sign, labeled with the sign; plain hands get no box, and the side overlay gets no hands at all (worker passes it hands=[]). A new sign = a HAND_SIGNS line + a HOLD_SECONDS entry + a SIGN_ACTIONS line.
- sign/renderer.py (numpy renderer for the 128x32 LED sign: NowPage/TodayPage/CalloutPage/SummaryPage, PreviewOutput for the website, PanelOutput for the real panels through Adafruit's Piomatter) + sign/glyphs.py (5x7 font and 16x16 icons as ASCII art) + sign/controller.py (which page shows, callout scrolling, ambient dimming during a block and at night, 8 fps loop). DAYANPI_SIGN = preview (default) | panel | off. The dashboard shows the preview in a smaller LED sign card under the camera and to-do cards (web/src/components/sign/SignCard.tsx), fetching GET /api/sign.png whenever the status's version changes.
- The sign uses GPIO 4, 5, 6, 12, 13, 16, 17, 20, 21, 22, 23, 26, 27 (the Matrix Bonnet also ties up 24), whether it goes through the bonnet or is wired straight to the header (docs/led-sign.md, "Without the bonnet").
- app.py calls logging.basicConfig(INFO) at import, because uvicorn only configures its own loggers and the app's INFO lines would otherwise never reach journalctl.
- vision/detector.py runs two ONNX models through plain OpenCV (cv2.dnn and cv2.FaceDetectorYN), so the Pi needs no new pip packages. The models live in models/ (the hand models are separate, see Hand signs): YOLO26 nano (COCO, exported at 640x480, the default export with output (1, 84, 6300), not the NMS-free (1, 300, 6) one; class 0 = person, 67 = cell phone) and YuNet for faces.
- Phones come from a second YOLO pass on a crop around the main person (person >= 0.5, box plus margin); full-frame phone hits are ignored. On my real desk frames (measured with YOLO11n; YOLO26n hasn't been measured yet) that took a phone in hand from 10% to 80% of checks at >= 0.3, with no hits while working. It roughly doubles the time per check.
- hardware/camera.py is the only thing that may open the camera. Inside the app, read frames from app.stream (camera.create_stream() picks the backend: DAYANPI_CAMERA = auto (default) | usb | picamera | both; PiCameraStream wraps picamera2 behind the same latest_frame/frame_after interface and skips USB webcams that libcamera also lists). Frame sizes differ by camera: the webcam is 640x480 (FRAME_WIDTH/HEIGHT), the Pi camera 768x432 (PICAMERA_WIDTH/HEIGHT, 16:9 like the sensor; a 4:3 size makes the ISP crop the Wide lens's sides). Nothing downstream may assume 640x480: the detector letterboxes any size into the model input, the zoom crop and YuNet use the frame's own size, overlays carry frame_width/frame_height, and the dashboard sets each feed's aspect ratio from the overlay or the picture itself. With both, app.stream is the front camera and app.side_stream the other one (camera.create_side_stream(), None for every other setting), served at /video/side, a 404 when there's no side camera. DAYANPI_FRONT_CAMERA = usb (default) | picamera picks the front one; a bad value warns once and means usb, and it's never read without both. Everything downstream (faces and poses, the side_* sample fields, /video vs /video/side, the Front/Side labels) goes by front vs side, never by USB vs Pi camera. camera.find_usb_device() finds the webcam: DAYANPI_USB_DEVICE if set, else the first /dev/v4l/by-id/*-video-index0, else /dev/video0, since /dev/video0 can move once a CSI camera is plugged in. DAYANPI_PICAMERA_ROTATION = 0 (default) | 180 flips every Pi camera stream (picamera, auto, front or side with both) through libcamera's Transform(hflip=1, vflip=1) in the camera's own ISP, read once per PiCameraStream; the webcam is never flipped. Both cameras go through the detector. The Camera card shows one feed at a time: when the status says side_camera, a flip button switches between front and side (web/src/components/camera/CameraCard.tsx, remembered in localStorage), and the page only opens the shown feed's stream, and only while peeking. Standalone tools like dayanpi.focus.check need `sudo systemctl stop dayanpi` first.
- Never save video or frames on the Pi, except the detector check's snapshots in focus_check/ (gitignored). Only state changes get logged.
- The site shows a camera pointed at me all day, so it stays on Tailscale Serve, not Funnel.

## Dashboard (web/)
- web/ is the dashboard's source: React + TypeScript + Vite + Tailwind CSS v4 + shadcn/ui, Lucide icons, Geist from @fontsource-variable (the page loads nothing from the internet; tests/test_app.py checks every file it links is a local /assets/ file). `npm run build` type-checks and writes dayanpi/static/ (Vite outDir, emptied first). dayanpi/static/ is build output: never edit it by hand, and commit it with every web/ change so the Pi never needs Node. The lockfile is committed; use `npm ci`.
- `npm run dev` proxies /api and /video to the Pi with DAYANPI_URL, DAYANPI_USER and DAYANPI_PASSWORD from web/.env.local (gitignored; web/.env.example has the names). Only vite.config.ts reads them, never the page. On the Pi the page relies on the browser's own Basic Auth login, same origin.
- Layout: src/components/<card>/ per card (header, focus, camera, todo, calendar, sign, pi; ui/ is shadcn's), src/hooks/ (useSnapshot: the one SSE stream, closed while the tab is hidden; useOverlayBoxes: the boxes over a feed; useFocusSegments; useNow; useTheme; useReplayOnChange), src/lib/ for pure helpers (format, timeline, boxes, pi, feeds, todos, calendar, markdown, motion, storage, types). Tests: Vitest + React Testing Library next to the code (`npm test`), plus pytest tests/test_app.py for the built page.
- src/styles/dashboard.css is the original hand-written stylesheet, kept whole and class-based; the JSX uses its class names, so the look didn't change. Tailwind and shadcn are for the to-do card and new pieces. src/index.css points shadcn's color names straight at the dashboard's tokens (--surface, --ink, --line...) instead of shadcn's own variables, because dashboard.css already uses --muted for gray text; the dark: variant follows data-theme on <html>, not a .dark class.
- Traps: `npx shadcn add` wrote `import { cn } from "cn"` and installed an unrelated npm package called cn; it should be `@/lib/utils`. tailwind-merge (cn()) reads custom colors like text-work as a font size and drops them, so don't pass two text-* classes through cn() when one is a custom color.
- The code rules apply in TypeScript too: noun-first components, verb-first functions, one return per function, objects instead of tuples from hooks.

## Rover (removed)
The 4WD rover code (motors, /api/drive, the Drive card, docs/rover.md) is gone for now but may come back. `git log --grep="Remove the rover"` finds the commit, and `git revert` on it restores everything, including the wiring notes that used to be here. Its motors use six of the LED panels' GPIO pins (12, 13, 17, 22, 23, 27), so this Pi can't run both.

## Python packages on the Pi
picamera2 comes from apt, and the venv sees it through system site packages: docs/MANUAL.md creates it with `python3 -m venv --system-site-packages .venv`. Don't add it to requirements.txt. For Mac tests, requirements-dev.txt pulls in requirements.txt plus pytest and httpx.

## Ground rules
- You can commit and push to main. One commit per step, with a message that says what changed, and only after the tests for what changed pass. Finish with the list of changed files.
- One step at a time. Stop when a step is done and wait for me.
- No calls to outside services or endpoints unless I explicitly say so for that run.
- Code style for new code: noun-first class names, verb-first function names, one return per function, no tuple returns, repeated code goes in a utils module, descriptive names for returned values, comments only for real traps. The existing code (app.py, hardware/camera.py, hardware/collector.py) doesn't all follow these; don't refactor it to match unless I ask.
- Finish every step with the tests you ran (only the ones covering what changed) and their results, plus the exact commands for me to test it on the Pi.
- Write docs (like docs/MANUAL.md) in plain, casual language.
